# 待测试

- Web 开发端画布落盘（v1.6.104）：`npm run dev` 后新建/编辑画布，仓库应出现 `data/canvas-dev/projects.json` 与 `blobs/`；换浏览器或 `localhost` ↔ `127.0.0.1` 打开同一 Vite，列表与内容应一致。若本地 IndexedDB 里已有旧画布且磁盘为空，首次打开应自动迁到该目录。

- Canvas.tsx 拆分为画布节点（v1.6.89–98）：对 canvasTsx 智能预览点「拆分为画布节点」— 应按**当前预览实际宽度**还原，并排图表/指标保持左右排布（不要被收成一列竖排）；图表块保留悬停 tooltip；静态卡片为矢量 HTML；可拖动/连线/双击改字。

- 智能预览 HTML 可拖动（v1.6.101–102）：Codex 生成或文件夹打开的 HTML 预览节点应可直接拖动，且拖动应流畅（接近文件夹智能预览）；需要点选页面内按钮时，悬停工具栏切到「交互」，拖节点再切回「移动」。顶部「HTML」标题条在交互模式下也可拖。

- 画布粘贴不被 HTML 预览挡住（v1.6.103）：选中或点过 HTML/智能预览节点后，在画布上 Ctrl+V 粘贴图片/文本仍应落到画布；在 Codex 输入框内粘贴仍进对话框。

- 导图连线直连与居中（v1.6.69 / v1.6.96）：让 Agent 生成上下主链 + 左右数据组的流程导图 — 主链上下应近似直线（bottom→top），不要从左右绕圈；侧向组应从近侧进出；主链节点水平居中（有左右分支时竖链仍应对齐）。改文案触发重排后也应如此。升级后需重启本地 Agent。

- 引用生成菜单连线落点（v1.6.99–100）：从节点左边/右边拖出松手出现「引用该节点生成」— 虚线应停在松手位置不跳动；菜单对边（左拖→菜单右边，右拖→菜单左边）贴齐该点。

- 滑块对比恢复（v1.6.68）：两张有内容的图片互相连线后，选中结果图左上角应出现「滑块对比」；开启后可拖竖线对照；仅含 `storageKey` 的参考图、连线方向反了也应可用；断线后旧对照不应残留。

- 导图不再整图吸组（v1.6.66）：让 Agent 生成带数据组的流程导图（节点初始坐标可重叠）— 主链 Step 不应全部进同一个绿色虚线框；组内叶子分开排列，整图不应堆成一团。可让 Agent「清掉重画」验证。

- Agent 中文夹箭头不横滑（v1.6.65）：对话出现含「A -> B」的中文说明（如「主链：任务识别 -> 看行业」）时应正文换行完整可见，不应出现等宽块底部横向滚动条。真 ASCII 箱线图仍可横滑。

- 底栏工具提示（v1.6.64）：点击左下角选择按钮切换到关联选择后，悬停提示应变为「关联选择」；再点一次变为「移动」，不再一直显示「选择」。

- 导图分步落盘（v1.6.63）：让 Agent 生成较大的 Skill/流程导图 — 应先出现主链，再按分支多次 `canvas_apply_ops` 扩展，最后才收尾补 label/打组/视口；不应单次 ops 把几十个节点堆在同一坐标。升级后需重启本地 Agent。

- 导图少蛛网（v1.6.62）：让 Agent 生成步骤较多的 Skill/流程导图 — 节点不应叠在同一点；连线应呈清晰主链（上→下或左右竖列），不要紫色蛛网；不应再调用 brainstorming/skill-blueprint。升级后需重启本地 Agent。

- 主题↔数据组流程布局（v1.6.61）：打开含「五看」类流程（主链经数据组串联、带中点 label）的画布，让 Agent 任意改一个导图节点文案触发重排 — 主链与两侧数据组应按连线方向居中分开，label 不贴节点；无成员的大虚线框应收成标题条，组内节点跟随组框移动且不互相叠压。

- 竖向导图间距与居中（v1.6.60）：Agent 生成带连线中点文字（如「总控入口」）和下划线标注的上下流程 — 主链节点应水平居中；节点之间给 label 留出空隙；标注不要盖住下一主题。升级后需重启本地 Agent。

- 判断分支 label（v1.6.59）：从六边形判断节点拖出/创建两个子主题 — 连线中点应依次出现「是」「否」；让 Agent 生成判断分叉时出边也须有分支文字。升级后需重启本地 Agent。

- 数据组消重叠（v1.6.58）：Agent 在数据组内放「主题 + 判断六边形」— 子节点应在父旁侧（或明显留白下方），不要压在父题上；组外节点也不应压进绿色虚线框。升级后需重启本地 Agent。

- 数据组按入线方向排布（v1.6.57）：Agent 生成带数据组、且多条线从**上方**进入的导图 — 组内成员应**横排**，不要瘦高竖列把顶上连线挤成一束；从侧向进入时仍可竖排。升级后需重启本地 Agent。

- 导图自由图（v1.6.56）：让 Agent 生成流程型导图 — 分支可出现在上/下/左/右及右上/右下，不被压成左右两列；上游可连到**绿色数据组框**再从组框连出；主题可连到独立 **smart-preview（.canvas.tsx）** 看板。升级后需重启本地 Agent。

- 可预览单文件直拖（v1.6.55）：将单个 `.canvas.tsx`（或 md/html/pdf/xlsx）拖入画布 — 应直接出现智能预览节点并显示内容，而不是先变成文件夹再拉线。整夹项目文件夹仍应落成文件夹节点。

- Agent 导图布局与层级（v1.6.54）：让 Agent 生成「五看」类大图 — 同列节点不重叠（间距按真实高度）；结构出现更深子主题，而非清一色「编号 → 提取/判断 → 一大段」；各主分支下详情簇有绿色数据组框，整图不被一个大虚线框包死。升级后需重启本地 Agent。

- 对话文件夹芯片与正文换行（v1.6.53）：将画布文件夹（如 skills）挂到对话并发送 — 用户气泡应显示带名称的文件夹芯片，不是裂图；助手中文回复应完整换行，不要出现横向滚动条（ASCII 流程图仍可横向滚动）。

- Skill 集合文件夹摘要预读（v1.6.52）：桌面版将截断后的 skills 文件夹（含 `folderTopLevelDirs`）挂到对话并发送 — 提示词应含「Skill 目录摘要」及各子目录 SKILL.md 解析出的名称/说明，不能仅因沙箱读不到路径就声称无正文。

- 超大 Skill 文件夹截断（v1.6.51）：桌面拖入整包 `.cursor/skills` — 节点界面仍可在 500 条后显示「已截断」，但 Codex 提示词应含完整一级子目录清单与磁盘绝对路径；已有节点需重新拖入以刷新元数据。

- 导图左侧收起（v1.6.50）：点击主题**左侧**连接点，应只收起/展开从该点**连出**的子分支，不隐藏从该侧连入的父节点；收起后端口显示 +，仍可拖出连线。右/上/下同理。

- Agent 导图 Step 2 读状态（v1.6.49）：Agent 添加连线 label / 判断节点后，`canvas_get_state` 应返回 `connections[].label`、节点样式，以及 `mindMaps` 中的连线清单；可让 Agent 读取后用 `canvas_update_connection` 改 label。升级后需重启本地 Agent。

- Agent 导图进阶 Step 1（v1.6.48）：让 Agent 用 MCP 添加 **decision** 六边形节点、**annotation** 虚线标注，以及一条带 **connection label** 的导图连线。升级后需重启本地 Agent。

- 导图左侧拖线（v1.6.47）：从主题**左侧**端口拖线连左侧子节点 — 预览与落线应保持左侧（父左→子右），不要自动跳到右侧端口。

- Codex 导图直接创建（v1.6.46）：给出明确主题要思维导图 — Agent 应立刻在画布创建节点，不要先问「确认按这个结构创建吗？」或调用 `superpowers:brainstorming`。升级后需重启本地 Agent。

- Codex 导图端口与布局（v1.6.45）：要左右分支的导图（如「亚马逊运营全流程」）— 中心应左侧连左分支、右侧连右分支，不要全部从右边绕线；上下端口在上下分支时可用；不要用虚线 `group` 包裹整张导图（除非用户要求）。升级后需重启本地 Agent。

- Codex 画布思维导图（v1.6.43）：要「生成思维导图 / 分析某某全流程」— 应在当前画布创建可编辑 mind-node 与紫色连线，而不是只写 `output/*.canvas.tsx`。升级后需重启本地 Agent 以重载 MCP/指令。

- Canvas 样式块展开修复（v1.6.24）：`infinite-canvas-features.canvas.tsx` 展开后应出现全部思维导图卡片（非仅 2 个 Callout），位置与预览一致，卡片样式/颜色/列表保留；原预览框变数据组外框。

- Canvas 样式块展开（v1.6.23）：已并入 v1.6.24 修复项。

- Canvas FlowDiagram 展开到画布（v1.6.21）：智能预览打开含 `FlowDiagram` 的 `.canvas.tsx` 后，工具栏应出现「展开到画布」；点击后在预览节点右侧生成导图节点与连线，可自由拖动、改文案、继续连线；无 FlowDiagram 或解析失败时应提示无法展开。

- 嵌套数据组随外层拖动（v1.6.20）：大组内再打小组后，拖动外层数据组框时，内层数据组及其成员应一起移动；新建内层组应继承外层 groupId；旧画布未写 groupId 的嵌套子组（中心落在外层框内）也应跟随。

- 缩放后点空白连线不错位（v1.6.19）：滚轮缩放后立刻点击空白取消选中，连线不应瞬间错位再恢复；多试几次不同缩放比例。

- 滑块对比上游优先（v1.6.18）：原图 → 工作台 → 生成结果 → 抠图等后续节点时，在中间结果上开滑块对比应对照上游原图/参考图，不应对照后面抠图结果；仅当确实没有上游对照时才兜底反向连线。

- 判断节点外形完整（v1.6.17）：六边形判断节点左右尖点与描边应完整显示，右侧不应被裁成竖直平边；菱形节点尖点同理。

- 判断节点连接点（v1.6.16）：六边形判断节点从左侧连接点拖线，预览与落线应从左侧尖点出发/接入，不应误用右侧；从右/上/下点拖线同理。从左侧点拖出新建子节点时，连线应接到父节点左侧。

- 图片进 PS 不弹 Camera Raw（v1.6.12）：新生成/下载的画布图片用 Photoshop 打开时，不应再因元数据弹出 Camera Raw（用户 PS 若设为「始终用 ACR 打开 JPEG」除外）。

- 连线输出箭头（v1.6.11）：导图/普通连线末端应有指向下游的实心箭头；标注连线仍为虚线+箭头，风格与原先一致。

- 导图指定边接入（v1.6.10）：从一主题拖线到另一主题的下连接点松手，连线应接到下点而非自动改到左边；拖到上/左/右点同理。已有连线再拖到另一边松手应更新接入边。

- 横向换行锚点固定（v1.6.9）：左右相连的主题编辑时按 Enter 增多行，左右连接点应保持原高度，不应随框变高上下移动。

- 编辑加宽锚点固定（v1.6.8）：从上方连入的子主题编辑加长文案时，上连接点/连线落点应保持原位，不应随框变宽往右跑。

- Tab 确认编辑（v1.6.7）：编辑导图或文本节点内容时按 Tab，应保存文案并退出编辑，不应插入制表符；未处于编辑时选中导图主题按 Tab 仍应新建子主题。

- 方向键新建导图（v1.6.6）：选中导图主题（非标注、非编辑态）按 ↑↓←→，应在对应方位新建节点；新节点外形/颜色/字号/判断或普通主题应与当前选中一致，并自动连线且进入编辑。

- 关联选择穿数据组（v1.6.5）：关联选择模式下点上游主题，应选中数据组、组内节点，以及从组内连出的下游判断节点（如「交付方式」）。

- 导图点连数据组保边（v1.6.4）：从主题下连接点拖到数据组边框松手后，连线应仍从下点出发接到组边，不应跳到右侧点或其它边。

- 数据组内单独拖动（v1.6.3）：选中数据组后，再点组内某个子节点应只选中该节点，拖动只移动该节点，不应再整组一起动；点组框空白处仍可选中/拖动整组。

- 数据组边框连线（v1.6.2）：从节点拖线到数据组时，可接到绿色虚线边框任意位置（不必找连接点）；松手后实线应落在松手处对应边框点；拖到组内子节点上仍应连子节点而非整组。

- 小节点拖动（v1.5.135）：小「子节点」悬停时拖动节点本体应能移动，不应轻易触发连线；上下连接点在选中后才显示，点的可点范围更小且在框外。

- 标注箭头方向（v1.5.134）：标注虚线箭头应指向被备注的原主题，而不是指向标注文字；从原节点拖出新建标注后方向也应正确。

- 拖线连接点高亮（v1.5.133）：从一个连接点拖线时，不应点亮其他所有节点的上下左右点；仅当前起点与靠近的吸附目标显示连接点。

- 标注落点（v1.5.132）：从上下点拖出选「标注」后，节点应出现在松手位置，不应弹回主题正上方/正下方。

- 菱形边线拉伸与尖点对齐（v1.5.131）：四个圆点应贴在菱形尖角上；按住菱形描边拖动能等比拉伸节点。

- 菱形按外形缩放（v1.5.130）：选中菱形/六边形不应再出现外围大方框；拖尖点缩放应贴着实际边框等比变化，连接点在选中时略外移以免抢缩放。

- 菱形/六边形连线对齐（v1.5.129）：连线应接到菱形尖角或六边形尖点上，尖点与线段之间不应留缝。

- 导图上点拖线（v1.5.128）：从上连接点拖出连线时不应被悬停工具栏挡住，也不应刚拖出就弹出「引用该导图节点生成」；工具栏在连线过程中应暂时隐藏。

- 导图上下点与缩放（v1.5.127）：选中导图节点时，上下圆点应能拖出连线/标注，不再触发上下边缩放；缩放请用四角。

- 标注节点（v1.5.126）：导图菜单可选「标注」；节点悬停可见上下连接点；拖出可建标注并用虚线箭头连到原节点；标注为下划线文字样式，不参与 Tab/Enter 分支树。

- 判断节点文字可读（v1.5.125）：六边形判断节点长文案或扁框时，文字应清晰可读，不应压成一条白线或整段消失。

- 菱形文字不越界（v1.5.124）：切到菱形或输入多行文案时，文字应落在菱形斜边内，不应穿过边框；框体应随内容合理放大。

- 判断框长文不消失（v1.5.123）：六边形判断节点内容较长或框被拉扁时，文字应缩小显示在框内，不应整段消失。

- 导图拉伸字号适配（v1.5.122）：拖拽缩放节点框时，文字应随框变大/变小，始终落在框内。

- 导图缩小不溢出（v1.5.121）：缩小画布视口时，主题文字应留在边框内，不应跑到框外；手动缩小的框内文字应同比缩小。

- 导图拉伸平滑（v1.5.120）：拖拽节点四角/边缩放时不应跳刷或被弹回；小节点拉伸不应突然跳到 220×160。

- 判断节点/菱形长文案（v1.5.119）：六边形判断节点输入较长中文时不应出现最后一字掉到框外；应折行并随内容增高。

- 导图长文本完整显示（v1.5.118）：字号较大或连续数字/长句不应在框右缘被截断；过长应折行并增高节点。

- 导图编辑无滚动条（v1.5.117）：字号放大或文字变长时，主题框应跟着变宽/变高，编辑区右侧不应再出现上下滚动箭头。

- 导图编辑不弹保存密码（v1.5.116）：双击主题改字并失焦后，Chrome 不应再弹出「要保存密码吗？」（用户名也不会变成主题文案）。

- 判断节点尺寸（v1.5.114 / v1.5.115）：新建「判断节点」应为贴合文案的扁六边形，「判断节点」四字单行不折行，大小接近普通子节点。

- 导图外形不被外壳裁切（v1.5.113）：选「直角」后节点四角应为尖角，不再保留外壳大圆角；菱形/六边形外形也应完整显示。

- 导图样式/颜色面板（v1.5.112）：悬停导图主题点「样式」应弹出可选外形（含菱形、圆形、两侧尖角六边形等），点「颜色」应弹出色板；不再单击轮换。

- 导图拉线专用菜单（v1.5.111）：从「中心主题」拉线到空白，菜单应为「引用该导图节点生成」，选项为「子节点 / 判断节点」，不应再出现文本/图片等基础节点。

- 思维导图双击创建（v1.5.110）：打开导图模式后双击空白，菜单应为「选择导图节点」（中心主题 / 分支主题），不是基础模式的文本/图片等列表；单击空白不再创建主题。

- 画布数据目录与文件夹复制：配置 → 偏好设置可改「数据目录」与「文件夹复制上限」（默认 500MB）。桌面版拖入小于上限的文件夹应复制到数据目录 `folders/<节点id>/`，节点底部提示已复制；超过上限应仅引用本机路径并提示，换路径后预览可能失效。浏览器环境仍走缓存预览，不一定真正复制到磁盘。
- Windows 桌面打包：在 `web/` 下执行 `npm run electron:pack` 应生成 `web/release/InfiniteCanvas-<version>-win-x64.exe`（NSIS，可改安装目录）与 `web/release/win-unpacked/InfiniteCanvas.exe`；安装或直接运行后应能打开应用。
- 桌面版画布/配置持久化：安装包内新建画布（改名或加节点）并配置渠道 API Key，完全退出后再打开，项目列表与「配置 → 渠道」应仍保留；本地 UI 应固定为 `http://127.0.0.1:17370`。覆盖安装升级后配置与画布也应保留。
- RunningHub auto 比例：选 nano-banana-pro 等图生图模型，比例为 auto（界面显示 1k · auto）时生成应成功，不应再报 `aspectRatio value empty`。
- 智能预览 CSV：文件夹中的 `.csv` 拉线到智能预览后，应显示可滚动的表格网格（表头+行列），而不是一整段带引号的逗号纯文本；重新点选该文件应能刷新旧的纯文本缓存。

- 智能预览多工作表：打开多 sheet 的 Excel 并选中某一表后，点预览标题旁「切换工作表」、工具栏同名按钮或「关闭预览」，应回到工作表列表并可另选；列表上的「重选」仍回到选文件。
- 智能预览 Excel 下游输入：多工作表文件选中某一表后，将智能预览连到工作台/Agent 等下游，@ 引用或生成输入应只有该表内容（可带表名），不应再是整夹摘要或其它工作表。
- 智能预览 Excel 全文进 Codex：对约 100 行×30 列的表，连线加入备选并 `@` 后发送，请求中应包含接近全表的 TSV（不应只剩十多行、二十来列后以 `…` 结束）；超大表才提示引用已截断。
- 安装版 RunningHub 请求：在全新安装的桌面版上（不配置任何 Key）对图片点「放大」，或使用 RH 综合节点，应能正常提交并出图，不应再报「鉴权失败，请检查 API Key、套餐权限或模型权限」；RunningHub 国际站模型在填入自己的 Key 后也应可用。
- 安装版假失败：在桌面安装版用 RunningHub 图生图（可故意在弱网下）生成，若渠道控制台已有 SUCCESS 结果，画布不应再因单次 query HTTP 500 立刻标红；偶发失败时文案应提示「任务可能已在后台成功」，而不是「请检查 API Key」。
- 生图错误详情：故意用错误 Key 或断网生图，结果节点应显示具体错误（如鉴权失败原文），而不是仅「全部图片生成失败」；鼠标悬停错误文字应出现完整错误 tip。
- 安装包图标一致：新打的 `InfiniteCanvas-*-win-x64.exe`、安装后的桌面/开始菜单快捷方式与窗口标题栏图标应为同一套山峰/A 形白标深底图标，不再出现安装包一个图标、安装后又一个 Electron 默认图标。
- 图片组展开态：一次生成多张图后点「N 张」展开，再点空白画布或取消选中，展开应保持；只有再点一次「N 张」才收起。
- Codex 鉴权失效自动恢复：在其他设备重新登录 Codex（或本机 `codex logout`）让当前登录失效后，用「Codex 生图」节点生成，侧栏应给出中文提示「Codex 鉴权已失效…」而不是反复刷英文 `refresh token was revoked`，画布顶部状态变为红色「Codex 鉴权失效」，任务管理器里旧的 codex app-server 应已退出；本机重新登录后不重启画布直接再生成，应能成功并恢复「Codex 已连接」。
- 内置 Agent 随画布退出：在应用内启动内置 Agent 并连接成功后关闭画布窗口，任务管理器中对应的 `node.exe`（及其下的 codex 进程）应一起消失，17371 端口释放；重新打开画布再点启动应能正常重新拉起。若 Agent 是在终端里自己起的，则不应被应用杀掉。
- 安装位置即数据位置：安装向导只有「选择安装位置」，不再出现单独的「选择数据目录」页；装完后用户数据应在安装目录下的 `data`（含 `.infinite-canvas-userdata`），偏好设置里「当前应用数据目录」应指向该路径。
- 图片节点上传保留配置：空图片节点先改模型、比例、张数，再点「上传图片」或「替换图片」后，底部提示栏配置应保持不变，不应回到全局默认。
- 残留 HTML/Markdown 插件：刷新或重新打开画布后，「选择节点」与底栏拼图扩展中不应再出现 HTML、Markdown；已画布上的旧插件节点可仍显示，但不应再能新建。
- Windows 卸载清数据选项：选「否」后安装目录下的 `data` 必须仍在（重装可接上）；选「是」应删除 `data`。旧版若 data-dir 曾指向自有夹（如 `D:\za`），只删应用子项，不得整夹清空。盘符根与盘符下第一层目录不得整夹删除。
- Windows 卸载清理 Input/Output：数据目录确定后，其下 `input` / `output` 应出现 `.infinite-canvas-io-dir`，安装目录或 `~/.infinite-canvas` 应有 `io-paths.txt`。卸载时若存在登记才会再问是否清理 IO；选「否」不删；选「是」只删带标记的已登记目录；无标记、盘符根、盘符下第一层（如 `D:\za`）与系统目录必须保留。
- 桌面版一键启动 Agent：本机未安装/未登录 Codex 时，方式二应显示未检测到 Codex 且「一键启动」不可用；安装 Codex 后应显示已检测，点击一键启动应拉起内置 Agent 并自动填入 Local URL / token 开始连接；无需本机安装 Node.js。连接后不应再弹出多个画布窗口或空白 Codex 控制台。
- 导出当前画布：含图片/视频节点与文件夹节点的画布导出 zip 除 `projects.json` 外应包含媒体文件与 `folders/...` 源文件；导入后图片与文件夹预览应能恢复。
- Midjourney 扩展参数：选择 RunningHub Midjourney（如 v7 / v8.1）后，图像设置应出现混乱/风格化/怪异/Raw 等控件；修改后重新生成应带上对应参数；自定义长宽比应写入提示词 `--ar`，且不出现错误的 auto 选项。
- 工作台输入色点：切换文生图/图生图（如 Midjourney vs gpt-image edit）时，绿色图片点数量与「需参考」描边应变化；Seedance/multimodal 视频模型应同时出现绿/蓝/黄点（图9/视频3/音频3）；连接参考图后对应实心点应高亮；不支持的模态整行隐藏；不应再显示「提示词 N 个」，文本/音频无媒体槽时整块输入区隐藏。
- 工作台默认高度：新建或重新打开旧默认高度的工作台时，「开始生成」下方不应再留大块空白；内容应紧凑贴底；用户手动拉高过的节点高度应保留。
- 工作台编辑提示词位置：「编辑提示词」应在「开始生成」下方，不再出现在输入槽位区域内部。
- 工作台槽位文字：输入区「提示词 / 图片 / 视频 / 音频」标签应单行显示，不换行。
- 工作台高度自适应：切到多槽位模型（如 Seedance multimodal）时节点应变高并完整显示「编辑提示词」；切回少槽位模型时应收紧，不再裁切或大块留白。
- 新建本地提示词：提示词中心搜索栏旁与空状态应有「新建提示词」；画布左侧「提示词库」搜索栏旁也应有「+ 添加」，填写标题与正文保存后出现在「我的提示词」；刷新后仍在；本地条目可编辑/删除；远程条目仍为复制/加入资产；侧栏可展开查看与插入。
- 提示词来源：首次安装或清空本地存储后，配置 → 提示词来源应为空，不预置内置来源；「删除全部」后刷新/重启仍为空；删除后提示词库与侧栏对应分类应为空，本地缓存一并清除。可手动「+ 新增来源」添加。
- 生图/视频创作台参数适配：生图工作台选 RunningHub Midjourney 时应出现混乱/风格化等扩展项而非固定质量/尺寸；视频创作台选 Seedance 等应出现对应秒数滑块/智能，选 KLING 等离散秒数仍为按钮；切换模型后面板选项应随之变化。
- 顶部导航品牌：首页等非画布页顶栏左侧应仅显示「无限画布」文字，不再出现 logo 图标。
- 节点滚轮缩放：鼠标悬停在工作台、智能预览（选文件/正文/Excel，不含 HTML iframe 内部）、音频控件、文件夹列表上时，滚轮应能正常放大/缩小画布；Shift+滚轮可滚动节点内列表/正文；打开「编辑提示词」或节点下方提示词输入区后，在输入区内滚轮仍应滚动文本而非缩放；打开图像/视频等设置弹层或张数弹层时，在弹层内滚轮应滚动面板内容而不缩放画布。
- 工作台编辑提示词高亮：提示词编辑器有内容，或已连接文本节点时，「编辑提示词」按钮文字、图标与边框应为绿色；清空编辑器且断开文本后恢复普通文字色与描边。
- 多文本拼提示词：工作台依次连接多个文本节点后生成，提示词应按连线顺序拼成一段正文（中间用空行分隔），不应再出现【文本1】【文本2】分块标签。
- 音频设置按模型能力：工作台选 RunningHub speech（如 speech-2.6-hd）应出现 MiniMax 音色与情绪；选 suno-single/custom、music-2.x、music-cover、声音克隆应显示对应设置。music-cover / 声音克隆工作台应出现黄色「音频 0/1」槽，未连参考音时「开始生成」不可点；连上音频并填写提示词后应能生成。语音类无参考音槽的模型不应显示音频槽。OpenAI TTS 仍为 alloy 等音色；仅 gpt-4o-mini-tts 显示声音指令。suno-lyrics 应提示歌词生成并产出文本节点。voice-design / preprocess 等仍可提示暂未接入。
- 视频设置按模型能力：RunningHub Seedance / Kling v3 等连续秒数应显示滑块，有智能时在左侧可选且选中后滑块禁用；LinkFox KLING 等 5s/10s 离散秒数仍为按钮；Veo Fast 仅 8s；Veo Lite/Pro 为 4/6/8s 按钮；方舟 Seedance 连续秒数同样用智能+滑块。
- 工作台命名：工具栏与节点标题应显示「工作台」（不再是「生成配置」）；节点内按钮与浮层标题应为「编辑提示词」（不再是「组装提示词」）。
- RunningHub 模型中文名：中文界面下列表应显示如 `midjourney-文生图-niji7`、`gpt-image-2.0/文生图·渠道低价`，基础名 midjourney/gpt-image 保持英文；英文界面仍为原 name_en。
- 模型名完整显示：生成配置打开 RunningHub 模型列表时，长名称应换行完整可见，不应被省略号截断；触发按钮悬停可见完整「渠道 · 模型」。
- 设置弹层双击输入：打开图像/视频等设置弹层后，双击 W/H 或其它输入框应只聚焦编辑，不应弹出画布「新建节点」菜单。
- 动态图像设置与张数按钮：工作台生图模式下，设置摘要不再带「N张」，右侧有独立张数按钮；点开后为滑块 + 右侧手动输入（1–15），拖动或输入后生成张数应生效；切换 RunningHub 模型后面板选项应随 registry 变化（如宽高比/分辨率）；LinkFox 仍显示通用质量/尺寸/透明背景。
- RunningHub 全量模型：RunningHub 渠道下生图约 95、生视频约 213、生文约 17（RHArt Text）、音频约 20；列表显示英文名（如 `nano-banana/...`、`google/veo3.1-fast/...`）；常用图/视频/文本模型仍应能按 endpoint 生成成功。
- RunningHub 国际站渠道：设置 → 渠道应出现「RunningHub 国际站」；填写国际站 API Key 后，生图可选 `rhart-image-v1/text-to-image`（无参考图）或 `rhart-image-v1/edit`（有参考图）；视频可选 `rhart-video-v3.1-fast/text-to-video` / `image-to-video`；文本可选 `rhart-text-g-3-flash-preview/text-to-text`。本地开发应走 `/api/runninghub` 代理到 `https://www.runninghub.ai/openapi/v2`，任务应能提交并轮询出结果。

- Skill 放到画布后拖动：在右侧「技能」列表点击「放到画布」后，再拖动图片或其他节点应保持流畅；技能列表打开时拖动画布也不应明显卡顿。
- 画布缩放 LOD：将缩放滚到约 30% 时，Excel / Markdown 等重内容应变为轻量外壳（图标+标题）；已有内容的图片/视频节点应显示等比缩小预览并保留淡描边；刚进入壳态时应接近清晰，继续缩小模糊才逐渐加重，不应一下子全糊；连线与选中仍可用；再放大到约 50% 时内容应自动恢复；在约 35%–42% 附近来回滚轮不应闪烁；缩小时框选或点选节点应保持壳态，不得把已隐藏的表格/正文重新展开。若多图已点开「N 张」展开副图，缩小画布后副图应仍保持展开，不要自动收回成叠图。
- 智能预览不重载：已选好文件（尤其 HTML 工程）的智能预览节点，缩小到壳态再放大应立即显示原页面，不应出现白屏重新加载，iframe 内滚动位置与图表状态应保持；把该节点滚动到视口外再滚回来同样不应重载；尚未选文件的智能预览节点仍按普通节点在缩小时收起。
- Input / Output 目录：设置 → 偏好设置不再单独填写 Input/Output；连接 Canvas Agent 后，工作区 `.infinite-canvas-paths.json` 应指向画布数据目录下的 `input` / `output`（默认安装目录 `data\canvas-data`，或自定义数据目录）。更改数据目录并失焦/浏览后应重新同步。

- 外部文字拖入：从飞书等应用选中文字拖到画布空文本节点（「双击编辑文字」）上应填入该节点；拖到已有内容的文本节点应替换；拖到空白处应新建文本节点；拖到 Excel 摘要节点上不应破坏其工作表结构（应在落点新建文本节点）。
- 智能预览节点：从文件夹节点拉线到空白处，「引用该节点生成」应出现「智能预览」；创建后先选 md/html/excel 等文件；Excel 多工作表时再选具体表；HTML 项目预览应接近浏览器直接打开（侧栏切换后主区有图表与正文，不应长期空白）；选中预览后节点内与悬停工具栏应有「全屏预览」「关闭预览」；全屏层点关闭应退出全屏，非全屏时关闭预览应回到选文件；将智能预览再连到配置/Codex 时，@ 与提示词应带上游「文件夹：xxx」而不是 HTML 全文；拖动上游文件夹不应导致预览反复刷新；若仍空白，删除旧文件夹节点后重新拖入整个项目文件夹再预览。
- 任意文件拖入：将 `.md` / `.pdf` / `.pptx` 等非媒体文件拖到画布应创建文件节点（列表，不直接显示正文）；图片/视频/音频/3D 模型（glb/gltf/obj 等）仍建对应媒体节点并可直接预览。从文件节点拉线创建「智能预览」后，已支持格式（md/excel/html/txt/pdf/ai/eps 等）可选中预览；不支持的格式仅留在文件列表、智能预览中不可选或提示无法预览。
- 模型节点：空白处「选择节点」应出现「模型」（在音频与工作台之间）。拖入 `.glb` / `.gltf` / `.obj` / `.stl` / `.fbx` 等应直接创建模型节点并静止预览（不自动旋转），无需再连智能预览；空节点可点上传。默认白膜（无贴图）、深色背景、交互关闭；选中后节点下方出现与节点等宽对齐的独立控制条（交互、深浅背景、白膜/贴图），悬停工具栏不再出现这三项；悬停工具栏「导出角度」应打开更大的微调弹窗（可与左侧导航同时操作），预览内左键拖动调视角、中键平移、右键调距离、滚轮调距离，拖蓝框边线移动选框、白点调框大小，并可选手动/固定/1:1 等比例；右侧参数显示两位小数；可将当前视角「设为初始角度」后提示词变化量归零；可切换深色/浅色预览背景；可点击或拖入左侧画布/资产中的图片作背景（自动切到该图长宽比），导出前可开关「导出时包含背景」；导出后生成高清（长边约 2048）图片节点，提示词为角度与镜头距离变化（不含平移）；「还原」可回到加载默认视角；点「交互」后才可轨道旋转/缩放，且拖转视角时节点本身不应被拖走；切回「移动」后视角应保持，不回到初始角度。单文件超过 32MB 应提示无法直接导入。文件夹内多文件 3D 仍可通过智能预览打开（默认亦为白膜、不自动转）。
- 「引用该节点生成」菜单：不应有小字说明；选项应与空白处「选择节点」一致（含组、Codex 生图、RH综合节点、智能预览等）；各行图标视觉尺寸应一致。
- Codex 添加画布内容：在画布选中图片/文本节点后，打开右侧 Codex 对话，点击输入框旁「添加画布选中为备选」（图层图标），应出现在右侧备选栏而非直接写入全文；输入 `@` 引用后发送才会带上内容；未选中时应提示先选中。
- Codex 连线落点：打开 Codex 面板后左侧中部应有圆点手柄；从画布节点右侧手柄拖线到该圆点松开，应在对话区右侧竖排出现备选（不立刻把全文塞进输入框）；输入 `@` 或点击备选后，输入框应出现图标芯片而非 `@[ref:…]` 明文；发送后仍带上对应节点内容；未 @ 的备选不应出现在请求里。
- 资产上传项目文件夹：左侧面板「资产」点「添加」→「项目文件夹」，选择整个项目目录后应出现「文件夹」分组资产（图标+名称+条目数）；拖到画布或点插入应生成文件夹节点，可再连智能预览查看内容；桌面版小于复制上限时应写入数据目录。
- 智能预览 PDF：连接文件节点后应显示 PDF 内容而非白屏；节点标题行不应再出现「全屏预览 / 关闭预览 / 重选」（这些只在顶部悬停工具栏）；若仍白屏可重新拖入该 PDF。
- 配置节点生成文本：模式为「文本」时点击开始生成，右侧应只出现 1 个「生成中」文本占位，不应按生图默认张数（如 3）创建多个占位；完成后写入该文本节点。生图模式仍按设置张数创建多个图片结果。
- 配置节点连接 Excel 后生成文本：将 Excel 连到「生成配置」，无论组装提示词是否 @ 表格，发送给 Codex 的提示词都应包含全部上游连线内容（各工作表文本等）；模型不应再回复「请上传表格」。@ 只把芯片换成可读标签，不用于筛选资源。
- Codex 对话提示词展示：从配置节点发起 Codex 文本生成后，右侧对话用户气泡应显示组装提示词里的原文（如「我收到的是一份 excel…」），而不是固定文案「【Codex 文本节点】请按系统设定生成文本」；且同一条提示词只出现一次。
- Codex 文本生成回写：配置节点用 Codex CLI 生成文本，右侧对话出现完整回复后，画布上的「生成中」文本节点应写入该回复并变为完成，不应一直转圈；停止按钮应恢复为「开始生成」。
- Excel 右侧 +/- 手柄：点击应展开/收起工作表或详情；按住拖出应开始连线到其他节点，松手完成连线；短点击不应误触发连线。
- 智能数据打组：Excel 展开多表后多选这些工作表节点，点击绿色打组或 Shift+G，应生成「数据组」（可带 Excel 文件名标题），组内提示已组合 N 份输入；数据组右侧可连到 Codex/配置，提示词中 `@` 数据组应展开为各表标题+文本；Agent 读取画布/选区时数据组应带有聚合文本。工具栏中间「组」仍可建空视觉框（无输出手柄）。输入框聚焦时 Shift+G 不应触发。
- Codex 生图状态复位：从 Codex 生图节点发起多张生图，右侧对话显示全部「内置生图 已完成」且结果图已出现在画布后，源节点应停止转圈并退出「Codex 生图中…」；生成过程中切换选中到结果图或关闭底部面板后，完成后仍应正确复位。
- 文件夹 SKILL.md 悬停预览：将含 `SKILL.md` 的 Skill 文件夹拖入画布后，鼠标悬停列表中的 `SKILL.md` 应显示 YAML frontmatter 中的 description（可带 Skill 名称），白底深字、全文展开无需滚动；无 description 时不弹出；旧节点若已导入同名 Codex Skill，也可回退显示其短说明。
- 图片滑块对比：带任务上传参考图的生成结果，鼠标移到图片左上角时应出现「滑块对比」开关；开启后默认与 image1 对照，可切换 image2（仅本任务上传参考图，不关联画布其它无关图片）；关闭后恢复原图；无参考图的节点不应出现该开关；开启对比时左上角不应出现浏览器坏图/破碎图标；左右两图应在同一画框内对齐，拖动竖线揭示对照，左侧不应缩成错位缩略图。多图展开后，鼠标在任一张结果图上按中键应仍能平移画布；副图顶部按钮应完整显示「下载 / 创建副本 / 设为主图」，不要截成「创…」「设…」。
- 视频节点交互：不再使用原生播放控件；选中后播放条在画面下方、提示词上方。画面区域拖动应能移动节点；点击画面不应播放/暂停，只由播放条左下角按钮控制。左键拖播放条只改进度/入出点，中键仍平移画布。
- 文档经智能预览：将 `.md` / `.csv` / `.xlsx` 拖入画布后应为文件节点而非文本节点；拉线到智能预览可选中并查看内容；Excel 多工作表应再选具体表。
- 文本节点 Markdown 预览：非编辑态应渲染标题、加粗、列表、代码块与表格；双击或进入编辑后仍显示并可修改 Markdown 原文；退出编辑后预览应同步更新；普通纯文本仍正常显示；鼠标在 Markdown / Excel 预览节点上滚轮应能放大也能缩小画布；按住 Shift 再滚轮应纵向滚动节点内容。
- Excel 摘要与展开：拖入多工作表 Excel 后，主节点默认只显示工作表名称与行列摘要，且工作表数量应与 Excel 底部标签一致（例如 6 个表不能只显示 4 个）；选中或悬停后右侧应出现加号，点击后在右侧为每个工作表各创建一个文本节点并连线；展开后加号变为减号，点击应收起并移除这些节点；工作表节点收起时仅少量预览，右侧加号应在当前节点内显示该表完整行列（仿 Excel 网格，可滚动，大表应通过虚拟滚动保持流畅），减号收起；各工作表「图片」列应显示嵌入图缩略图（不只显示「图片」文字），刷新页面后重新展开仍应可见；主节点 `@` 引用可为截断文本，但不得因此丢掉未写入引用的工作表。
- Codex CLI 生图 @ 引用：将 Codex Skill、含 SKILL.md 的文件夹、图片或文本节点连到 Codex CLI 生图节点后，在提示词中输入 `@` 应弹出可选资源；选中后插入引用芯片；生成时应加载被 `@` 的 Skill（文件夹需已导入 Codex Skills）、把引用文本写入提示词、仅附带被引用的图片（仍可使用本地面上传的参考图）；未使用 `@` 时仍自动使用已连接 Skill，并附带全部上游参考图。
- Agent 一键启动方式二：在本地 `npm run dev` 下打开 Agent 连接设置，点击方式二「一键启动」应通过 Vite 拉起 `npx -y @basketikun/canvas-agent`，自动填入 Local URL / Connect token 并开始连接；Agent 已在运行时应直接连接且不重复启动；非本地开发环境应提示改用终端命令。
- 画布选择与平移：左下工具栏应能切换「选择」与「移动」模式并用图标显示当前模式；选择模式拖动空白区域应显示疏朗清晰的虚线框，虚线长度、间距和粗细在任意缩放比例下保持一致；移动模式应能从空白区域或节点上拖动画布。按住 Control 或空格应临时反转当前工具且不改变工具栏模式，即选择变移动、移动变范围选择；点击画布页任意按钮后按空格应只临时切换工具，不得再次触发该按钮；输入框和可编辑文本内仍可正常输入空格。中键平移以及 Shift/Cmd 追加选择节点应继续可用。
- Alt+选中复制节点：按住 Alt 点击节点应立即复制该节点（偏移放置并选中副本）；按住 Alt 拖动节点应拖动副本而非原节点；Ctrl 临时平移与 Shift/Cmd 追加选择不受影响。
- 侧栏拖入画布：左侧「资产」中的图片/视频/文本，以及「提示词库」中的提示词，应可直接拖到画布空白处并在落点创建对应节点；原有点击「+」插入（居中）仍可用。
- 文档站国际化：访问文档站首页及 `/docs` 应默认显示英文，切换简体中文后 URL 应带 `/zh-CN` 且首页、顶部导航、侧边栏、正文、搜索框和页面操作文案均显示中文；刷新、站内跳转和再次切回 English 后语言应保持正确，搜索结果与 Markdown/LLM 文档内容不得混入另一种语言。
- 国际化基础框架：从页面右上角切换简体中文或 English 后，首页、顶部及移动端导航、版本弹窗、配置主面板、渠道编辑、模型选择、页面标题、页面描述和 Ant Design 内置文案应立即切换，刷新页面后保持所选语言；偏好设置中不应再显示语言选项，WebDAV 同步错误、提示词来源及其他尚未接入翻译的业务模块暂时仍可能显示中文。
- 全局弹层主题：全站 Dropdown、Menu、Select、Cascader、TreeSelect 等弹层在浅色主题下应使用白色背景、轻灰悬停和选中态，在深色主题下应使用深色背景与低对比度浅色交互态，不应再出现默认黑灰色块、文字对比不足或单个页面配色不一致。
- 画布节点缩放稳定性：选中任意节点并反复拖动四角缩放时，节点工具条应在缩放期间隐藏、松开后恢复，页面不应再出现 `Maximum update depth exceeded`。
- Agent MCP 初始化状态：首次进入空白对话、点击「新对话」或恢复历史对话后，无需先发送消息，对话区应立即显示 Codex 会话准备，并列出 `codex_apps`、`infinite-canvas`、`node_repl` 等完整 MCP 服务状态；全部服务进入终态前可输入并保留草稿，但发送按钮、上传和回车提交应禁用；可选 MCP 失败时应提示警告但允许发送，`infinite-canvas` 缺失或失败时应阻止发送并显示明确原因；首轮及后续任务运行期间再次收到的 MCP 状态只进入诊断日志，模型开始处理及回复完成后对话区不应残留初始化卡片。
- Agent 模型设置：连接 Canvas Agent 后，输入框左下方应显示当前 Codex 模型与推理强度；模型列表应来自当前账号实际可用模型且不显示内部审查模型或重复项，切换模型后强度选项随模型能力更新且无空白选项，刷新页面后保留选择，发送任务时实际使用所选模型和强度；本地控制台与右侧「日志」应记录本轮使用的模型和推理强度。
- Agent 新对话响应：一轮对话完成后点击「新对话」，聊天内容应在服务端确认切换后清空并进入空白对话；后台应串行创建线程并预热 MCP，多个标签页应按同一会话版本同步，旧 HTTP 响应不得覆盖较新的 SSE 状态，初始化完成前不能发送到上一条会话或重复创建线程；重启 Agent 后应重新恢复并预热已有活动线程，无法恢复的失效空线程应自动替换为可用的新线程。
- Agent 读取画布卡片：读取当前画布完成后，卡片应按非零类型显示文本、图片、配置、视频、音频、分组、其他节点及连线数量，例如「3 个文本、5 张图片、2 个配置、4 条连线」；空画布应显示「当前画布为空」，执行失败时仍应显示错误信息，刷新恢复历史后统计保持一致。
- Agent 首次发送响应：在空白新对话中输入内容并按回车后，输入框应立即清空、用户消息应立即出现在对话中，再显示「正在思考」；线程创建或发送失败时，原输入和附件应恢复；任务运行期间输入的新草稿不应在请求成功后被清空。
- Agent 动态工具信息：执行内置生图、查看图片、命令、文件修改或其他动态工具时，卡片标题应显示具体工具名称；执行失败时正文应显示真实错误原因，刷新并恢复历史对话后仍应保持一致，不再统一显示「工具操作已完成」。
- Agent 画布生图：重启 Canvas Agent 后，其自动生成的工作区 `AGENTS.md` 应同步为最新版指令（用户自行编写的其他 `AGENTS.md` 不应被覆盖）；输入“生成一张图片”时应调用 `canvas_generate_image`，通过当前画布节点创建并运行生成流程；只有明确输入“使用 Codex 内置生图/ImageGen 技能生成”时才允许调用内置能力，Codex App Server 返回的 `imageGeneration` 结果应显示在对话中并作为保持原比例的图片节点添加到当前画布；Agent 不应在没有生成结果时提前声称“已生成”。
- Agent 顶部栏：在对话、历史和日志之间新增「技能」标签并显示已加载数量；连接状态应位于左侧 Agent 标题旁，并与右侧新对话使用相同规格的文字按钮，只有内容标签显示选中线；标签图标始终显示，中英文模式下都应按标签区域的实际可用宽度隐藏文字并保留小号数量，空间足够时显示图标和文字，拖动宽度时不应裁切、换行、横向滚动或错位。
- Agent 输入框窄屏布局：底部上传、Skill、确认模式、权限模式、模型和思考程度控件在窄面板下应只显示图标，宽面板下恢复文字；所有纯图标操作悬停时应使用统一样式显示名称或当前状态，任意宽度都不出现横向溢出。
- Agent 本地 Skill 管理：连接 Canvas Agent 后进入「技能」，应能读取当前 Codex 工作空间发现的项目、个人、系统和管理员 Skill，并支持搜索、按范围筛选、刷新及启停；未能加载的 Skill 应通过可点击、可滚动的详情查看原因；画布在站点工作空间 `.agents/skills` 下创建的 Skill 应可新建、编辑和删除，其他来源只读且不得被画布改写；编辑期间文件被其他窗口修改时应拒绝覆盖，清空显示名称、短说明和默认提示词后旧值应被删除，同时保留图标、品牌色等未由当前界面管理的元数据；多个标签页同时连接时，任一页面的 Skill 变更应自动同步，断开或切换 Agent 时旧请求不得重新写回列表或弹出编辑器。
- Agent Skill 草稿生成：创建 Skill 时应提供「空白创建」「从当前对话生成草稿」「从当前画布生成草稿」三种入口；空对话不得发起生成，取消时不得写入文件，确认后才写入站点工作空间 `.agents/skills`；Agent 运行中应禁用生成，多标签页下对话和画布来源必须分别严格绑定发起请求的 `threadId` 和 `clientId`，生成期间外部 MCP 仍应操作最近聚焦页面；草稿运行时创建、启停、删除和更新 Skill 应被统一拒绝，点击停止应真实中断临时草稿 turn；草稿不得泄露本地路径、密钥、媒体数据、真实节点 ID 或任务进度等临时状态，普通中文斜杠文本与 `/imagine` 等命令必须保持完整，生成草稿使用的临时 turn 不得出现在 Agent 对话、历史或日志中。
- Agent Skill 调用：在技能页点击「使用」或在输入框左下方选择 Skill 后，输入框上方应显示可移除标签；发送任务时应通过 Codex 原生结构化 Skill 输入执行，而不是只把名称拼进普通提示词，发送成功后清除选择，失败时保留；新建对话、断开连接、Skill 被停用或删除时也应清除失效选择，发送前、任务完成后和刷新历史后的用户消息文字应保持一致。
- Agent Markdown 样式：右侧 Agent 回复中的代码块应为横向占满消息区域、无语言标题和无双层边框的紧凑代码条，单行内容不应保留纵向大面积空白，复制操作仅在悬停时弱化显示；行内代码、链接在浅色和深色主题下应清晰；点击外部链接后应显示中文紧凑确认弹窗，长路径能够正常换行且复制、继续打开和关闭操作可用；点击 `/Users/`、`/home/` 等本地绝对文件路径时应改为提示在系统文件管理器中定位，支持复制路径，且浏览器地址不应跳转为 localhost 文件路径。
- Agent 工具确认模式：右侧面板标题栏不应再显示「工具确认」开关；对话输入框左下方应显示确认模式选择，默认选中「自动确认」，画布写入工具应直接执行；切换为「手动确认」后，画布写入工具应在对话中展示等待确认卡片，并支持批准或拒绝。
- Canvas Agent Codex 升级：启动 Canvas Agent 后应输出 Canvas Agent、内置 Codex 和本机 Codex 版本，实际运行的内置 Codex 应为 0.146.0；内置与本机版本不一致、未安装本机 Codex，或 npm 存在更新版本时应显示对应升级提醒，npm 检查失败不应阻止服务启动；Agent 应能正常连接 Codex、创建或恢复会话、发送消息并调用画布工具，运行中停止任务应只中断当前 turn，随后无需重启 Agent 即可继续发送新任务。
- Canvas Agent Debug：普通启动应通过公共 logger 输出 Info、Warn 和 Error 日志；使用 `npx -y @basketikun/canvas-agent --debug` 启动后还应输出 Debug 日志并显示日志文件路径，终端统一采用“`YYYY-MM-DD HH:mm:ss` 级别 消息 详情”的纯文本单行格式，`~/.infinite-canvas/logs/` 下应按启动日期生成相同格式的 `canvas-agent-YYYY-MM-DD.log`，同一天多次启动应追加到同一文件；日志中不应出现连接 token 或图片 Data URL 原文。
- Canvas Agent Codex 日志：Codex app-server 输出带颜色或样式控制符及 UTC 时间的 stderr 时，本地日志和网页诊断日志应只显示一份 `YYYY-MM-DD HH:mm:ss` 本地时间和干净文本，不应出现重复 ISO 时间或 `[2m`、`[31m` 等 ANSI 转义内容。
- Agent HTTP 诊断日志：网页发送一条普通消息后，本地 Debug 日志不应重复输出 `/health`、`/canvas/state`、`/canvas/activate` 成功请求、流式增量或完整会话响应，只保留 HTTP 请求与 Codex 生命周期摘要；右侧「日志」应以单行时间线展示发送、开始、回复、工具、完成用量和错误，不再输出 userMessage started/completed、流式摘要、重复 threadId 或大段原始 JSON。
- Agent 排查日志：右侧「日志」中的排查视图应显示连接摘要，并可按错误、警告和信息筛选；向下查看日志时仅列表内部滚动，标题、连接状态、筛选数量和操作按钮保持固定；连续相同事件应折叠计数，单条日志可展开查看完整详情；原始 JSON、复制全部、复制最近错误和清空功能应继续可用，浅色与深色主题下均应清晰。
- Agent 排查日志顺序与跟随：日志应按时间从旧到新排列，进入日志或切换筛选时定位到最新事件；停留底部时自动跟随新日志，展开最后一条后应继续停留在完整详情底部，向上浏览后暂停跟随并显示与对话区视觉高度一致的居中圆形向下箭头，新日志数量只在悬浮提示中显示；列表底部不应出现额外留白，点击按钮后回到底部并恢复跟随。
- Agent 对话统计：用户消息应右对齐并使用透明无气泡的简洁排版，用户和 Codex 两侧均不显示人物头像，消息下方均不显示时间或 Token 信息；输入框上方应居中展示最新一次模型调用的输入、缓存、输出 Token 用量，不显示会话累计值，数值更新时应从旧值平滑滚动到新值而非突然跳变，新建、切换或删除当前会话后应清空旧统计。
- Agent 回复实时显示：在右侧 Agent 发送消息后，用户消息下方应立即出现“正在思考...”，任务运行期间不应闪退；工具完成后应显示 Codex 正在继续处理及已等待时长，等待超过 30 秒时提示可继续等待或停止本轮；Codex 的回复应在当前对话中持续显示，实时事件缺失时也应在任务完成后自动同步完整内容，无需切换到历史或日志再返回对话。模型繁忙等任务失败时应立即结束等待状态，在对话中显示中文错误原因和重试建议，诊断日志不应再把失败轮次记为“处理完成”，刷新历史后错误仍应保留。新建尚未发送首条消息的空会话不应反复出现历史读取失败。
- Agent 对话实时与历史一致性：运行包含思考、命令及画布工具的较长任务，在执行中刷新发起页面或打开第二个页面时，已出现的用户消息、思考过程、工具卡和回复前缀均应保留并继续更新；同一思考或工具只显示一张卡片，任务结束及再次刷新后内容、顺序和状态应一致。切换页面焦点不能改变本轮画布工具目标，发起页面断开后不得把图片或写操作转交其他画布，使用相同页面身份重连后才能继续处理。
- Agent 流式交互性能：发送长回复时文字应连续平滑出现，输入框、滚动和画布操作不应随回复变长而明显卡顿；长历史会话中只有当前流式消息持续更新，屏幕外消息不应造成明显布局压力；任务完成后应通过 SSE 自动同步完整历史，不再持续请求 `/health` 轮询状态。
- Agent 过程时间线：新建 Agent 对话后 Codex 应生成可读思考摘要，并在运行时依次显示中文的思考摘要、执行计划、命令执行、网页搜索、文件修改和画布工具活动；思考摘要的图标、标题和箭头应稳定保持在同一行，默认收起且无边框，点击箭头后才展开 Codex 实际返回的具体摘要，其中 Markdown 强调、列表和代码应正确渲染而非显示原始符号，多行代码块和文本流程图应保留原始换行并允许横向滚动，完成事件不应再用「已完成分析」覆盖已经收到的摘要；同一轮连续命令应合并为显示数量的无边框折叠行，折叠时不显示命令预览，单条展开后直接显示详情，多条展开后可逐条查看工作目录、耗时、退出状态和运行输出；其他工具调用继续使用紧凑卡片排版，状态图标、标题和状态文字保持在同一行；结构化任务进度不应混在对话时间线中，而应独立放在对话区下方、Token 统计上方，支持展开和折叠，并逐项实时更新「待处理」「进行中」「已完成」状态；新任务生成时默认展开，任务结束后保留最新结果，同一计划更新不应生成重复内容；文件详情展示文件路径与新增/修改/删除动作，工具详情不应出现请求 ID、英文工具名或原始 JSON；一轮对话结束自动同步历史以及刷新页面后从历史中 resume 对话时，思考摘要、命令和工具过程记录仍应完整保留并保持相同展示。
- Agent 权限控制：输入框可选择「请求批准」「自动审查」「完全访问」；请求批准模式下，Codex 编辑工作区外文件、执行受限命令或访问网络时应在对话中显示审批卡片，支持拒绝、允许一次和本会话允许，并能依次处理多个并发请求；提交决定后卡片应保持禁用等待，只有 Codex 确认处理后才移除；等待审批时刷新页面，未处理的审批卡应自动恢复且不能让任务永久卡住；自动审查模式应仅将需要用户决定的风险操作送入审批；完全访问必须先显示风险确认，启用后可访问网络和本机文件且不再请求审批；选择应在刷新后保留。
- Agent 历史记录：点击记录卡片应直接进入对应对话，不再显示「进入」按钮；可勾选单条或全选多条记录并批量删除，删除当前对话后聊天内容应清空。
- Agent 默认新对话：每次进入任一画布并连接 Agent 后，对话区应保持空白且不自动恢复上一次会话，并在后台创建新线程、预热 MCP；需要继续旧对话时可在「历史」中主动选择恢复。
- Agent 当前画布优先：在已打开某个画布时要求 Agent 创建、修改、整理或生成内容，Agent 应直接读取并操作当前画布，不应先调用 `canvas_list_projects` 或使用 `site_navigate` 重复进入画布；只有明确要求查看或切换其他画布时才允许查询画布列表并导航。
- Agent 图片消息：发送一张或多张图片附件后，图片应紧跟用户文字并在消息右侧显示为约 40px 的紧凑缩略图，不再撑大消息区域，单击缩略图应打开大图预览，打开或关闭预览不应改变消息间距或产生额外空行；任务运行中、完成同步历史、切换页面及重新进入历史对话后都应显示浏览器本地保存的图片缩略图，不应消失或把 attachmentId、附件使用说明等内部上下文回显到用户消息中；删除历史会话后应同步清理对应缩略图。
- 画布文本复制：在 Agent 对话或节点信息详情中用鼠标选中文字后，按 `Ctrl/Cmd + C` 应复制所选文本，不应触发画布节点复制；未选中文字且焦点位于画布时，原有节点复制快捷键应保持可用。
- Agent 工作目录指令：`canvas-agent/agent-instructions.md` 应作为独立维护源；重启 Canvas Agent 后，当前工作目录应自动生成 `AGENTS.md`；新建对话发送消息时，Codex 日志中的用户消息只包含本轮请求和必要的附件上下文，不再重复整段 Infinite Canvas 前置提示词，画布及工作台工具仍可正常调用。
- 画布文本设置：文本节点和生成配置节点切换到文本模式后应显示推理强度设置，可选择自动、低、中、高、极高；选择自动时默认 OpenAI Responses 请求不应携带 `reasoning`，选择其他档位时应携带所选强度，刷新画布后节点设置应保留；文本模型自定义调用脚本应能读取 `reasoningEffort`，OpenAI 模板应按自动或指定档位正确组装请求。
- 生图工作台参考图：将一张或多张图片拖入参考图区域后应直接上传并显示缩略图；拖入非图片文件应忽略，拖动过程中区域应显示高亮提示，放下文件不应导致浏览器打开或替换当前页面。
- 工作台历史图片清理：生图或视频工作台生成内容后，在「我的素材」删除图片、删除画布图片节点、清空画布或删除画布，再次打开对应生成记录时，历史缩略图、结果图片和参考图仍应正常显示；删除生成记录时，其专属本地文件仍应正常清理。
- 视频创作台参考资产：将图片、MP4/MOV 视频或 MP3/WAV 音频拖入任一参考资产区域后，应按文件类型自动上传到对应列表；当前拖入区域应显示高亮提示，原有数量、大小、时长和格式限制应继续生效。
- 画布组装提示词：输入或连接超长提示词后，浮层正文高度不应继续撑大，内容应可在正文区域内滚动查看和编辑，标题及关闭按钮保持可见。
- 画布节点提示词：图片等节点下方的提示词超过输入区域高度后，鼠标悬停在输入区域内滚动应查看提示词内容，不应缩放画布。
- 画布节点提示词回显：单图或多图生成完成后，切换选择生成结果的根节点及任一子节点，下方输入区域都应继续显示生成时的提示词；切换到其他节点再选回来后也不应清空。
- 画布生成配置：连接文本节点后连续点击生成（包含失败重试），组装提示词不应重复追加上游文本；在生图、文本、视频、音频之间切换时，实际请求应始终使用当前面板展示的对应类型模型。
- 画布多图生成：开始生成 N 张图片后应立即创建一个包含 N 个可展开槽位的图片节点，并且来源到结果只保留一条连线；生成期间空槽位应独立显示生成中或失败，任何已有图片内容的槽位都必须始终显示图片，任意图片率先成功后应立即成为主图并展示，不等待其他请求完成；收起状态应最多显示三层紧密错开的背板，避免占用过多画布空间，右上角应显示醒目的「N 张」数量提示；点击数量后，浮动工具条应暂时隐藏，各图片槽位应从当前节点向右上方整齐展开；已成功图片的「设为主图」应常驻显示，并在亮色、深色主题及不同图片背景上保持清晰；点击画布空白处应自动收起并恢复工具条。
- 画布多图主图切换：点击「设为主图」后，节点中心和当前最长边应保持不变，仅按新图片比例调整另一条边；自由变形节点应完全保持现有宽高，画布视口及左下角缩放值不应变化。
- 画布多图失败槽位：包括当前主槽位在内的每个失败槽位都应显示「重试」和「删除」；重试只更新当前槽位，已有成功主图时不得抢占主图；删除只移除当前失败槽位并同步更新图片数量。
- 画布多图尺寸调整：子图展开时开始拖动尺寸控制点，应先收起图片组一次，再正常调整根节点尺寸，不应触发 React 循环更新或应用错误页。
- 画布左侧元素列表：点击元素整行应平滑定位并选中对应节点，自动缩放不得超过 100%；有内容的图片元素应显示预览按钮，点击后打开大图弹窗且不触发画布定位。
- 配置与用户偏好：导出 JSON 后应包含渠道、默认模型、生成偏好、提示词来源和 WebDAV 配置；在修改当前配置后重新导入该文件，应恢复导出时的设置，错误 JSON 文件应提示格式不正确。配置文件包含 API Key 和 WebDAV 凭据，不应公开分享。
- 本地存储设置：配置页应显示「本地存储」Tab，进入后只读取 `infinite-canvas` 数据库，自动统计 IndexedDB 占用、站点总占用、浏览器配额与使用率，并按对象仓库显示记录数及内容体积；新增或删除图片、音视频、生成记录后点击刷新，数据应同步变化，统计期间页面保持可操作。
- 模型渠道协议：渠道编辑可选择「火山方舟」并自动填入方舟接口地址；任意名称的生图模型应按方舟 JSON 格式提交参考图，任意名称的视频模型应按方舟任务格式提交和查询，不再依赖模型名包含 `doubao`、`seedream` 或 `seedance`；1080p 不应再因模型名包含 `fast` 被禁用，参考视频应允许最大 200MB、总像素 409600-8295044，并继续校验官方宽高、比例和时长限制。
- 图片编辑弹窗：遮罩、切图和裁剪连续滚轮缩放时，图片与遮罩应保持同步且不再闪烁、短暂消失或跳动；遮罩画笔圆心应始终固定在鼠标位置，仅直径随缩放变化，缩放后仍可准确涂抹、拖动切分线和调整裁剪框。
- 提示词中心布局：页面标题及提示词总数应居中；连续输入搜索文字时应在停止输入约 300ms 后再查询；桌面端分类与标签应在左侧独立滚动，右侧搜索框下直接展示提示词卡片；标签数量较多时不能继续向下挤压提示词，窄屏下应恢复上下排列且内容不溢出；不再显示「我的提示词」Tab，收藏提示词应直接加入我的资产。
- 提示词详情弹窗：封面和参考图应固定显示在上方，复制及加入资产操作栏固定在底部，只有中间的标签、描述及提示词内容区域可以滚动；弹窗宽高应受视口限制且不超出屏幕。
