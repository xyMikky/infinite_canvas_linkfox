# 画布升级与保存保护实施计划

目标：升级、读取失败与并发保存都不能静默覆盖已有画布；发生故障时保留可导出的原始数据与明确错误。

约束：沿用 IndexedDB/localforage、现有开发磁盘目录和固定桌面 origin；本次用户明确要求旧版本升级，因此保留并读取已有数据来源。按项目约定不运行构建、语法检查或浏览器自动验收；安装升级与故障注入列入待手动验证，不承诺未经验证的绝对保证。

1. 存储入口：集中校验画布快照；初始化完成前禁止业务写入。识别旧 localStorage 副本，只在主存储缺失时复制，原件保留；有两份不同数据时将旧副本保存为恢复快照。
2. 保存：开发端使用基于文件摘要的条件写入；浏览器使用 Web Locks 串行读比对写，旧窗口的状态不得覆盖新版本。保存失败显示持久提示，内存内容可导出，刷新前提示未保存。
3. 备份：首次读取旧数据时先保留升级原件；正常保存保留非空历史快照，支持从画布库下载恢复 ZIP。主记录缺失但历史存在时进入恢复态。素材清理须保留历史引用，读取失败或保存未完成时不清理。
4. 桌面：保留固定端口与已有数据目录；目录不可用时停止启动并提示，不再回退空目录。
5. 安装：在调用旧卸载器之前复制并校验用户数据到安装目录外；复制失败中止升级；安装后恢复丢失文件并保留原数据目录指向。旧版卸载器即使删除安装目录，独立副本仍保留。
6. 收尾：更新版本与变更记录，补充升级矩阵（旧自定义目录、默认目录、换安装位置、读写失败、并发旧窗口、缺失主文件、恢复素材）；用户手动验收通过前不发布正式安装包。

已实现以上保护并通过 30 项隔离数据专项检查。即使初始化完成，未经明确删除操作的全量空列表也会被阻止写入。真实 NSIS 升级与浏览器 UI/IndexedDB 验收保留在 pending-test；素材自动删除已暂停，后续回收站另列 TODO。

安装阶段设计依据：[NSIS 官方章节执行顺序与 Unicode 文件读写](https://nsis.sourceforge.io/Docs/Chapter4.html)；结合仓库内 electron-builder 模板，隐藏备份节声明在主安装节之前。
