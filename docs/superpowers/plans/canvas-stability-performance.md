# 画布稳定性与大画布性能实施计划

**目标：** 减少连续编辑时的整库保存、大导图连线计算和屏幕外预览运行，保留数据保护与原有交互。

**依据：** 用户已选择「稳定性与大画布性能」方向并授权优化；沿用当前 Zustand、RBush、React Activity 和本地存储结构。

## 约束

- 不改用户项目数据，不迁移存储结构，不绕过备份、并发覆盖校验和明确删除保护。
- 不运行构建、语法检查或浏览器自动验收；用隔离数据做针对性的行为检查和计算基准，真实手感交给用户确认。
- 不重写画布，不改无关功能；保持星小驰接点、导图交叉抬桥、组框端口和预览内部状态。

## 实施步骤

- [x] 保存：无实际变化不更新项目引用；短窗口合并连续写入，保留未保存提示、主动重试与离开页面的保存保护。
- [x] 连线：交叉检测使用已有 RBush 筛选候选；缓存未变化曲线的采样，并剔除视口外曲线绘制，保持跨屏长线可见。
- [x] 预览：尚未进入视口的重预览不提前挂载；已访问预览移出视口后休眠并保留状态，选中与操作中的节点保持显示。
- [x] 稳定性：补查项目恢复失败和切换项目时的失效拖拽回调，避免旧交互影响新画布。
- [x] 使用 200 / 500 / 1000 条曲线与隔离存储做专项回归，记录计算结果及人工验收边界；同步版本和待测试文档。

**验收重点：** 连续修改只保存最新完整快照；保存失败不丢内存修改；画布切换不串项目；曲线可见性包含控制点外拱；优化前后交叉抬桥一致；屏幕外已访问预览保留状态且不持续运行 React 副作用。

**验证记录：** 35 项 Node 专项检查通过（13 项持久化、10 项磁盘/HTTP、5 项桌面目录、4 项曲线数学、3 项可见性策略）。固定样例中 1000 条曲线重复交叉计算约 16.30 → 2.37 ms，单条移动后约 16.51 → 2.43 ms。曲线基准不包含 DOM、端口布局、WebGL 或浏览器合成，不能据此宣称实际画布帧率。运行命令与人工项目验收项见 pending-test。
